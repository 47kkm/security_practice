# Level 30 --> 31

## 문제 개요
`bandit30` 계정의 비밀번호를 이용해 주어진 깃 저장소를 클론하고 다음 레벨 비밀번호를 획득한다.

## 풀이과정
1. `git clone` 명령어를 이용하여 저장소 클론
2. 로컬에서 클론한 디렉터리에 접근
3. README.md 파일 확인 --> 정보 없음
4. 브랜치 확인 --> 정보 없음
5. 커밋 로그 확인 --> 정보 없음
6. `git tag` 명령어로 태그 목록 확인
7. `git show` 로 태그 내용 확인 및 비밀번호 획득

## 핵심 개념
1. git tag
```bash
# 태그 목록 확인
git tag

# 현재 HEAD 커밋에 태그 생성
git tag [태그명]

# 특정 커밋에 태그 생성
git tag [커밋id]
```
- tag 는 특정 시점의 스냅샷이다.
- 특정 커밋에 붙여서 버전 지점으로 고정해두는 기능이다.
- 주로 `v1.0.0`, `v2.1.3` 처럼 배포 버전을 표시하거나 중요한 릴리즈 시점을 기록한다.
- 특정 커밋을 나중에 정확하게 찾거나, 배포 버전을 롤백할 수 있다.
- `git show` 명령어를 사용하여 태그 내용을 확인할 수 있다.

## 보안 관점 분석
- tag 기반 정보 은닉 및 노출 취약점

## 위험 요소
- tag 메시지에 민감 정보가 포함되면 탈취될 수 있다.
- tag 도 코드의 일부로 보아야 한다.
- tag 는 보여지지 않기 때문에 검토 및 확인에서 쉽게 빠지는 영역이다.

## 대응 방안
- tag 에 민감 정보 저장 금지
- 릴리즈 시 tag 내용 함께 확인
- 불필요 tag 정리
