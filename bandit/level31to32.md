# Level 31 --> 32

## 문제 개요
`bandit31` 계정의 비밀번호를 이용해 주어진 깃 저장소를 클론하고 다음 레벨 비밀번호를 획득한다.

## 풀이 과정
1. `git clone` 명령어를 이용하여 저장소 클론
2. 로컬에서 클론한 디렉터리에 접근
3. README.md 파일 확인
4. 파일 내 지시대로 `key.txt` 파일을 만든다.
5. `git status` 를 통해 파일 변화가 없음을 확인한다.
6. `.gitingore` 확인
7. `git add -f`를 이용해 `key.txt` 파일을 스테이지에 올리고 커밋한다.
8. `git push`를 이용해 푸시

## 핵심 개념
1. .gitignore
```bash
# txt 확장자인 모든 파일 제외
*.txt
```
- 특정 파일, 또는 특정 패턴의 파일들을 git 관리 대상에서 제외한다.

2. git add
```bash
# 스테이지에 파일 추가
git add [파일명]

# 변경이 있는 모든 파일 추가
git add .

# 강제 파일 추가 (ignore 무시함)
git add -f [파일명]
```

## 보안 관점 분석
- 클라이언트, 서버 검증 구조
  - .gitignore 등을 통해 파일 푸시가 불가능 하도록 설정할 수 있지만, 이를 쉽게 우회할 수 있으므로 검증은 서버에서 수행해야 한다.
- .gitignore 파일은 보안을 위한 파일이 아니라 불필요한 파일을 푸시하지 않게 하기 위한 제약이라고 보아야 한다. (ex. node module 등)

## 위험 요소
- 클라이언트 측에서만 검증을 수행하는 경우 이를 쉽게 우회할 수 있다.

## 대응 방안
- `pre-receive hook` 을 통한 서버 측 검증
  - git 에서 원격저장소에 push 를 받기 직전에 실행되는 검사 스크립트
  - 통과 시 push 성공, 실패시 `pre-receive hook declined`
- push 권한 제한 등 접근 제어
