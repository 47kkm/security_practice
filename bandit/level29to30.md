# Level 29 --> 30

## 문제 개요
`bandit29` 계정의 비밀번호를 이용해 주어진 깃 저장소를 클론하고 다음 레벨 비밀번호를 획득한다.

## 풀이 과정
1. `git clone` 명령어를 이용하여 저장소 클론
2. 로컬에서 클론한 디렉터리에 접근
3. README.md 파일 확인
4. `<no passwords in production!>` 메시지 확인
5. `git branch` 명령어로 브랜치 리스트 확인
6. `git checkout` 명령어로 `dev`브랜치 체크아웃
7. `README.md` 파일 재확인 및 비밀번호 획득

## 핵심 개념
1. git branch
```bash
git branch
git branch -r
git branch -a
```
- `기본` - 로컬 브랜치 목록 확인
- `-r` - 원격 브랜치 목록 확인
- `-a` - 모든 브랜치 목록 확인

2. git checkout
```bash
# 해당 브랜치로 이동
git checkout [브랜치명]

# 새 브랜치 생성 및 바로 이동
git checkout -b [브랜치명]

# 특정 커밋으로 이동하기
git checkout [커밋id]

# 수정한 파일을 마지막 커밋 상태로 되돌림
git checkout -- [파일명]

# 변경사항 무시하고 강제 이동
git checkout -f [브랜치명]
```

3. git 브랜치의 특성
- 브랜치마다 독립된 공간으로, 다른 코드가 존재할 수 있다.

## 보안 관점 분석
- 브랜치 기반 정보 노출 취약점
- 브랜치도 하나의 공격 표면이 될 수 있다.
- 공격자는 단일 브랜치가 아닌 모든 브랜치를 확인할 수도 있다.

## 위험 요소
- `dev`등의 개발용 브랜치에 민감 정보를 저장하면 쉽게 탈취될 수 있다.
- 브랜치를 보안 경계로 생각하면 안 된다.
- 브랜치 관리 실수에 의해 민감 정보가 노출될 수 있다.

## 대응 방안
- main(master) 외 모든 브랜치를 적절하게 관리
- 민감 정보 하드 코딩 금지
- 브랜치 접근 권한 제한
- 미사용 브랜치, 불필요 브랜치 정리
