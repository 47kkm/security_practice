# Level 15 --> 16

## 문제 개요
SSL/TLS 가 적용된 서비스 포트(30001)에서 `bandit15`의 비밀번호를 이용하여 다음 레벨의 비밀번호를 획득한다.

## 풀이 과정
1. ssh 서버 로그인
2. `nc` 명령어를 통한 접근 시 실패 확인 (평문 통신이므로)
3. `ncat` 명령어를 이용하여 SSL/TLS 연결 생성 및 메시지 전송
4. 응답으로 비밀번호 획득

## 핵심개념
1. ncat
```bash
ncat [옵션] [호스트] [포트번호]
```
- 네트워크 연결, 데이터 송수신, SSL/TLS 를 지원하는 도구
- nc(netcat) 보다 보안, 기능이 강화
- 기능
  - 서버 열기
  - 클라이언트 접속
  - TLS 암호화
  - 파일 전송

2. ncat 주요 옵션
```bash
ncat -l [포트번호]
ncat --ssl [호스트] [포트번호]
ncat -v [호스트] [포트번호]
ncat -u [호스트] [포트번호]
ncat -w [seconds] [호스트] [포트번호]
```
- `-l` - listen. 포트 열고 대기
- `--ssl` - SSL/TLS 암호화 연결
- `-v` - 상세 출력
- `-u` - udp 사용
- `-w` - timeout. seconds 초 후 자동 종료

3. 사용 예시
```bash
# localhost 5000번 포트에 TLS 통신으로 메시지 보내기
$ echo "hello" | ncat --ssl localhost 5000
```
```bash
# 5000번 포트로 들어오는 데이터를 받아서 file.txt 로 저장하기
$ ncat -l 5000 > file.txt
```
```bash
# file.txt 내용을 5000번 포트로 전송
$ ncat localhost 5000 < file.txt 
```
```bash
# 192.168.0.10 호스트의 80번 포트 열려있는지 확인
ncat -zv 192.168.0.10 80
```

## 보안 관점 분석
- 암호화된 네트워트 통신의 이해
- 평문 통신 시에 민감 정보가 포함되면 해당 데이터가 그대로 노출되므로 SSL/TLS 암호화 통신을 이용하는 것이 안전

## 위험 요소
- SSL/TLS 미적용 시 네트워크 구간에서 스니핑을 통해 민감 정보 탈취가 가능하다.

## 대응 방안
- SSL/TLS 서비스 적용
- 평문 통신 프로토콜 사용 금지
- 내부 통신 역시 암호화
