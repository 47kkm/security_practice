# Level 22 --> 23

## 문제 개요
`/etc/cron.d/` 경로에 있는 파일을 확인하여 어떤 명령이 수행될지를 확인한 후 다음 레벨의 비밀번호를 획득한다.

## 풀이과정
1. ssh 서버 로그인
2. `/etc/cron.d/` 경로 이동
3. `ls` 명령어를 통해 파일 리스트 확인 및 다음 레벨 비밀번호 관련 파일 확인
4. `cat`을 이용해 해당 파일 읽고, 예정된 스케줄 작업 확인하기
5. 스케줄에 작성된 명령어를 직접 수행하여 비밀번호가 저장될 파일명 획득
6. 해당 파일로 접근하여 비밀번호 획득

## 핵심 개념
1. 해시 기반 파일명 생성
- 사용자 입력값을 기반으로 해시를 적용한다.
- 추출된 해시값을 파일명으로 사용한다.

2. md5 해시
- message digest algorithm 5
- 임의 길이의 데이터를 입력 받아 고정 길이(128비트 = 32자리 16진수)의 문자열로 바꿔주는 해시 함수
- 입력값이 같으면, 해시값도 동일하게 생성된다.
- 주로 파일 무결성 확인으로 사용한다.
- 충돌(Collision) 가능으로 현재는 보안용으로 부적합하다.
  - 충돌(Collision) --> 서로 다른 값을 입력했는데 동일한 해시 결과 발생 

3. md5sum
```bash
# 텍스트 md5 해시 계산
echo "hello" | md5sum
```
```bash
# 파일 md5 해시 계산
md5sum [파일명]
```
- 원본 파일의 md5 해시값을 미리 전달 받음
- 전달 받은 파일의 md5 해시값을 직접 계산
- 두 해시값 비교를 통해 파일 무결성 확인

## 보안 관점 분석
- md5 등의 안전하지 않은 해시 알고리즘 사용으로 인해 결과값을 예측 가능
- 예측 가능한 값으로 민감 정보 노출

## 위험 요소
- cron 자동화 작업과 누구나 접근 가능한 위치로의 파일 저장으로 인해 권한 상관 없이 민감 정보가 노출 된다.
- 예측 가능한 값으로 민감 정보가 저장된 디렉터리를 손쉽게 파악할 수 있다.
- 해시를 썼다고 해서 안전한 것은 아니다.

## 대응 방안
- 예측 불가능한 랜덤값 사용
- `/tmp` 사용 최소화
  - 공용 디렉터리에 민감 정보 저장하지 않기
- 파일 권한 제한
