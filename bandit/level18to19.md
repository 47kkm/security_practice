# Level 18 --> 19

## 문제 개요
ssh 로그인 시 실행되는 `.bashrc` 파일을 누군가가 조작하여 로그인 후 바로 로그아웃 되고 있다. 홈 디렉터리에 있는 `readme` 파일 내 다음 비밀번호를 획득해야 한다.

## 풀이 과정
1. ssh 서버 로그인
2. 바로 로그아웃 되는 현상 확인
3. 로그인 명령어에 `/bin/sh` 를 추가하여 `.bashrc`를 읽지 않고 우회하여 로그인 하도록 처리
4. `readme` 내의 비밀번호 획득 

## 핵심 개념
1. .bashrc
- 터미널을 사용할 때 자동으로 적용되는 개인 설정 스크립트이다.
- 사용 예시
  - 긴 명령 줄이기
  ```bash
  # ll 만 입력해도 ls -al 이 실행된다.
  alias ll='ls -al'
  ```
  - 경로(PATH) 추가
  ```bash
  # /my/tools 경로를 환경변수 설정하여 쉽게 접근
  export PATH=$PATH:/my/tools
  ```
  - 자동 실행
  ```bash
  # 터미널 접속하자 마자 /work 디렉터리로 이동 
  cd ~/work
  ```

2. .bashrc 주의해야 할 점
- .bashrc 는 1) 새로운 터미널을 열 때, 2) ssh 접속하여 쉘을 시작할 때 자동 실행된다.
- 자동으로 실행되기 때문에 해당 파일에 이상한 코드나 악의적인 코드가 삽입되면 로그인 할 때 마다 해당 코드가 실행되게 된다.
  ```bash
  exit
  ``` 
  - 해당 코드가 들어가게 되면, 로그인 하자 마자 바로 종료되는 현상 발생

3. .bashrc 에 문제가 있는 경우
```bash
ssh [user]@[host] /bin/sh
```
- .bashrc 를 읽지 않는 쉘을 통해 접속한다. (우회)
- 우회 장점
  - 깨진 .bashrc 를 무시할 수 있다.
  - 로그인이 막힌 상황을 복구할 수 있다.
- 우회 단점
  - alias, PATH 등 자동 설정이 작동하지 않는다.
  - 프롬프트가 없이 보인다. (`******$ ` 의 프롬프트 표기 없음)

4. ssh 원격 명령 실행
```bash
$ ssh [user]@[host] "cat ~/readme"
```
- 로그인 + 명령 실행을 한 번에 수행한다.
- shell 이 실행되기 전에 명령을 먼저 수행하게 된다.
- 따라서 .bashrc 가 실행되기 전에 cat 이 먼저 실행된다.

## 보안 관점 분석
- 접근 제한 우회 기법을 이해
- `.bashrc` 설정의 주의점 이해

## 위험
- shell 접근을 제한하는 것만으로는 공격을 막을 수 없다.
- shell 접근을 제한하더라도 우회가 가능하면 무력화 된다.

## 대응 방안
- `ForceCommand` 설정
  - 사용자가 무엇을 입력하든 이 명령만 실행한다.
  - 서버 설정 예시
    ```bash
    ForceCommand /usr/bin/whatever
    ```
  - 위 처럼 설정 시 `"cat ~/readme"` 등의 명령어를 로그인 시 추가해도 강제로 `/usr/bin/whatever` 가 실행된다.
- `chroot`, 컨테이너 격리
  - 사용자가 볼 수 있는 파일 시스템을 따로 만든다.
  - 공격자가 `cat /etc/passwd`를 수행해도 가짜 파일이 보여진다.
- 최소 권한 유지
