# Level 19 --> 20

## 문제 개요
`bandit19` 계정에서는 `/etc/bandit_pass/bandit20` 파일을 읽을 수 없다. 동일 디렉터리에 존재하는 `bandit20-do` 파일을 이용하면 `bandit20` 권한으로 명령을 실행할 수 있다.

## 풀이 과정
1. ssh 서버 로그인
2. `/etc/bandit_pass/bandit20` 읽기 시도시 권한 오류 발생 확인
3. `ls -l` 을 이용해 파일권한 확인 및 `bandit20-do` 파일의 setuid 비트 확인
4. 해당 파일 실행
5. 해당 파일 프로그램을 통해 `cat` 명령어를 이용, `/etc/bandit_pass/bandit20` 파일을 읽어 비밀번호 획득

## 핵심 개념
1. setuid
```bash
$ ls -l
-rwsr-x--- 1 bandit20 bandit19 14888 Apr  3 15:17 bandit20-do
```
- 권한
  - `r` - 읽기 (4)
  - `w` - 쓰기 (2)
  - `x` - 실행 (1)
  - [파일, 디렉터리표기][소유자권한 `rwx`][소유그룹권한 `rwx`][제3자권한 `rwx`]
- setuid 가 설정되면
  - 파일 실행 시 파일 소유자의 권한으로 동작한다.
  - 소유자 권한의 실행필드(x)가 `s`, `S`로 변경된다.
    - `s` - (소문자) 실행 권한 있음
    - `S` - (대문자) 실행 권한 없음

cf) setgid
- setgid 가 설정되면
  - 파일 실행 시 파일 소유그룹의 권한으로 동작한다.
  - 소유그룹 권한의 실행필드(x)가  `s`, `S`로 변경된다.

cf) sticky bit
- 스티키비트가 설정되면
  - 파일 소유자와 root 만 파일을 변경 및 삭제할 수 있다.
  - 제3자 권한의 실행필드가(x)가 `t`, `T`로 변경된다.

2. 현재 경로 파일 실행하기
```bash
./[파일명] [argument]
```
- `./[파일명]`으로 현재 경로의 파일을 실행한다.
- `argument` 가 필요한 경우 함께 넘겨서 사용할 수 있다.

3. 타 경로 파일 실행하기
```bash
/home/user/~~/[파일명] [argument]
```
- 절대 경로로 실행하기
  - 루트(/) 부터 전체 경로를 써서 실행한다.
  - 어디서 실행하든 항상 동작한다.

```bash
../../bin/~~/[파일명] [argument]
```
- 상대 경로로 실행하기
  - 현재 위치 기준으로 이동하면서 파일 경로를 찾아 실행한다.

## 보안 관점 분석
- setuid, setgid 등이 설정된 파일을 통해 권한 상승이 발생할 수 있음을 인지

## 위험 요소
- setuid 설정이 잘못 되어 있으면 root 권한이 탈취되거나, root 권한의 쉘 획득 등이 발생할 수 있다.

## 대응 방안
- 불필요한 setuid 제거
- 최소 권한 적용
