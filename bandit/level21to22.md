# Level 21 --> 22

## 문제 개요
`/etc/cron.d/` 경로에 있는 파일을 확인하여 어떤 명령이 수행될지를 확인한 후 다음 레벨의 비밀번호를 획득한다.

## 풀이 과정
1. ssh 서버 로그인
2. `/etc/cron.d/` 경로 이동
3. `ls` 명령어를 통해 파일 리스트 확인 및 다음 레벨 비밀번호 관련 파일 확인
4. `cat`을 이용해 해당 파일 읽고, 예정된 스케줄 작업 확인하기
5. 스케줄에 따라 실행된 명령어를 기반으로 비밀번호가 저장된 파일 확인 및 비밀번호 획득

## 핵심 개념
1. cron
- 스크립트나 명령어를 특정 시간, 날짜, 또는 주기적인 간격으로 자동 실행하는 시간 기반 작업 스케줄러
- 백업, 리포트 생성, 시스템 유지 관리 등 반복적인 작업의 자동화가 필요할 때 사용한다.

2.주요 명령어
```bash
# 리눅스
crontab -e [사용자]
crontab -l [사용자]
crontab -r [사용자]

# 유닉스
crontab -u [사용자] -e
crontab -u [사용자] -l
crontab -u [사용자] -r
```
- `-e` - 사용자의 크론탭 설정 편집
- `-l` - 사용자의 크론탭 목록 확인
- `-r` - 사용자의 크론탭 설정 삭제
- [사용자] 를 명시하지 않으면 현재 로그인된 사용자를 의미한다.

3. cron 표현식
```bash
* * * * * 명령어
```
- 분 / 시 / 일 / 월 / 요일 / 명령어
- 분: 0 ~ 59
- 시: 0 ~ 23
- 일: 1 ~ 31
- 월: 1 ~ 12
- 요일: 0 ~ 6 (0 부터 차례로 일요일)
- `*`는 모든 값을 의미한다. (매분, 매시, 매일, 매월, 매요일)

4. 표현식 예시
- `0 0 * * * /home/user/script.sh` - 매일 0시 0분에 /home/user/script.sh 실행
- `10 5 * * 0 /path/to/backup.sh` - 매주 일요일 5시 10분에 /path/to/backup.sh 실행

## 보안 관점 분석
- 자동화로 인한 정보의 노출
- 스케줄 작업으로 모든 사용자가 접근 가능한 `/tmp` 하위로 민감 정보 이동

## 위험 요소
- cron 자동화 작업과 누구나 접근 가능한 위치로의 파일 저장으로 인해 민감 정보가 노출 된다.
- 권한이 없어도 이동된 파일을 읽어 정보를 획득할 수 있다.
- 자동화된 작업은 계속해서 반복되기 때문에 더 위험할 수 있다.

## 대응 방안
- 민감 정보 저장 위치 제한
  - `/root` 또는 제한된 디렉터리를 이용
- 파일 권한 최소화
- cron 실행 권한 점검
  - 어떤 사용자 권한으로 실행되는지 확인 필요
  - 높은 권한으로 실행되는 작업은 더 주의해야 한다.
- 민감 정보 직접 노출 금지
  - 민감정보는 파일로 저장하기 말고 메모리에서 처리한다.
