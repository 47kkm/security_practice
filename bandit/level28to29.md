# Level 28 --> 29

## 문제 개요
`bandit28` 계정의 비밀번호를 이용해 주어진 깃 저장소를 클론하고 다음 레벨 비밀번호를 획득한다.

## 풀이 과정
1. `git clone` 명령어를 이용하여 저장소 클론
2. 로컬에서 클론한 디렉터리에 접근
3. README.md 파일 확인
4. `password: xxxxxx` 의 형태로 마스킹된 패스워드 정보 확인
5. `git log` 명령어를 통해 커밋 로그 확인
6. `git show` 명령어를 통해 비밀번호 마스킹 처리로 추정되는 커밋 로그 확인
7. 마스킹 전 비밀번호 획득

## 핵심 개념
1. git log
```bash
git log
```
- 커밋 히스토리를 확인할 수 있다.
- 즉 파일을 지우거나 내용을 수정해도, 커밋 로그를 통해 히스토리를 파악할 수 있다.

2. git show
```bash
git show [commit id]
```
- 커밋 id 를 파라미터로 넘겨, 해당 커밋에서 변경된 내용을 확인할 수 있다.

## 보안 관점 분석
- 히스토리 기반 정보 유출 취약점
- 민감 정보 내용을 지운다고 해도, 과거 이력 확인(일종의 포렌식이라고 볼 수 있겠다.)을 통해 민감 정보를 획득할 수 있다.

## 위험 요소
- 코드 자체가 아닌 히스토리를 공격 포인트로 삼을 수 있다.
- 민감 정보를 삭제했다고 해서 안전한 것이 아니다.

## 대응 방안
- 민감 정보 커밋 금지
- 불필요 히스토리 삭제 등 관리
