# Level 13 --> 14

## 문제 개요
다음 레벨의 비밀번호는 `/etc/bandit_pass/bandit14` 에 저장되어 있으나, 현재 사용자(`bandit13`)는 해당 파일을 읽을 수 있는 권한이 없다.
대신 ssh private key 가 제공되며, 이를 이용해 다른 사용자(`bandit14`)로 로그인 한다.

## 풀이 과정
1. ssh 서버 로그인
2. `sshkey.private` 파일 확인
3. `scp` 명령어를 이용해 해당 파일을 로컬에 내려 받기
4. 내려 받은 key 파일을 이용하여 `bandit14`계정으로 로그인
5. `/etc/bandit_pass/bandit14` 파일 내 비밀번호 획득 

## 핵심 개념
1. sshkey.private
- ssh 로그인용 비밀번호 대신 쓰이는 키 파일. 2개의 키(개인키, 공개키)를 이용해 로그인한다.
  - Private key (개인키): 로그인을 위해 사용자만이 가지고 있는 키 (공유되어서는 안 된다.)
  - Public key (공개키): 서버에 등록된 키 (노출되어도 된다.)
- 로그인 과정
  - 사용자 PC에서 Private key 를 이용 --> ssh 접속 시도 --> 서버 Public key 를 이용해 검증 --> 로그인 성공
- 일반적으로 비밀번호를 이용한 로그인보다 보안상 더 안전하다.

2. sshkey 를 이용해 로그인하기
```bash
ssh -i sshkey.private [user]@[host] -p [포트번호 (22번인 경우 생략)]
```
- 참고 [ssh 접근](./level0.md)

3. scp
- ssh 를 이용해서 파일을 복사하는 명령어
- 동작 과정
  - ssh 로그인 --> 인증 (비밀번호 or 키) --> 파일전송
  - scp 명령어 수행 시 로그인이 요구된다.
  - 따라서 ssh 가 작동하지 않으면 scp 도 작동하지 않는다.

- 서버 --> 로컬 (다운로드)
  ```bash
  scp -P [포트번호 (22번인 경우 생략)] [user]@[host]:[원격 파일 경로] [로컬경로] 
  ```
- 로컬 --> 서버 (업로드)
  ```bash
  scp [로컬 파일 경로] [user]@[host]:[서버 경로]
  ```
- 포트 번호 지정 시 대문자 `-P` 사용

## 보안 관점 분석
- 한 계정으로 침입 후, 다른 계정 로그인 정보 획득 및 접근을 통해 권한 상승 및 확장이 가능하다.
- 특정 파일에 대해 권한이 있는 계정으로 바꾸어 파일에 접근한다.

## 위험 요소
- private key 가 유출되면 비밀번호 없이 서버 접근이 가능하다.
- 웹서버에 키를 업로드 해두거나, 평문 저장 해두거나, 권한 설정을 잘못하여 키가 유출되어 권한 상승 발생 가능

## 대응 방안
- private key 외부 노출 금지
- `chmod` 를 이용한 적절한 권한 설정
- 키를 주기적으로 교체
